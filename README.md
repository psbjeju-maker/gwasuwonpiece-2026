# 황금 귤을 찾아라 — 사용 설명

행사장 GPS 보물찾기 게임. **앱 설치 없이 모바일 웹**으로 돌아간다.
지금은 Firebase 없이 **각 폰 안에서만** 동작하는 상태다 (플레이·테스트는 완전히 가능).

> **2026-08-29 개정**: 참가자가 QR을 찍어 다니던 방식(40개)을 폐기하고,
> 나침반이 가장 가까운 미발견 지점을 가리키는 **GPS 나침반 방식**으로 전면 교체했다.
> 도착 반경 안에 들어오면 자동으로 퀴즈가 뜬다. 이유·경위는 볼트의
> `QR 보물찾기 개발 명세서.md`(2026-08-26)와 `GPS 나침반형 보물찾기 프로토타입.md`(2026-08-28~29)를 참고.
> **미션 완료용 QR(스태프 명찰, M01 등)은 그대로 남아있다** — 없어진 건 보물찾기 QR 40개뿐.

## 1. 바로 열어보기

Desktop 폴더에서 `serve.py`를 켠 다음:

| 화면 | 주소 |
|---|---|
| 참가자 | http://localhost:8000/과수원피스_할로윈_1031/game/ |
| 운영자 | http://localhost:8000/과수원피스_할로윈_1031/game/admin.html |
| GPS 좌표 찍기(현장 답사용) | http://localhost:8000/과수원피스_할로윈_1031/game/gps_picker.html |

운영자 PIN은 **6842** (운영자 화면 → 최종 정답 탭에서 변경 가능).

> GPS·방향센서는 `localhost`가 아니면 대부분 **https**여야 브라우저가 허용한다.
> 로컬 http 서버(`serve.py`)로는 폰에서 위치 권한이 막힐 수 있으니, 실제 나침반 테스트는
> Firebase 배포 주소(https)나 폰에 내려받은 파일(file://)로 하는 게 안전하다.

## 2. 파일이 하는 일

| 파일 | 내용 |
|---|---|
| `index.html` | 참가자 화면 전부 (등록 → 나침반 → 퀴즈 → 최종 → 쿠폰) |
| `admin.html` | 운영자 화면 (진행현황·정답설정·퀴즈편집·GPS 지점·데이터) |
| `data.js` | **여기가 콘텐츠다.** GPS 지점(gpsPoints) 13개, 퀴즈 41문제, 최종 정답, 미션 |
| `app.js` | 게임 로직 (나침반 방위·거리 계산 포함) |
| `store.js` | 저장 담당. Firebase를 붙이는 자리도 여기 |
| `style.css` | 참가자 화면 디자인 |
| `sw.js` | 오프라인 대응 (한 번 열어두면 신호 없어도 게임이 열림) |
| `gps_picker.html` | 현장 답사 때 각 지점의 실제 위경도를 찍는 도구 |
| `make_qr.py` | 미션 완료 QR(스태프 명찰용) 인쇄 시트 만드는 스크립트 |
| `map_picker.html` | (폐기됨) 옛 X마커 지도용 % 좌표 찍기 도구 |
| `out/` | 만들어진 미션 QR 이미지와 인쇄 시트 |

## 3. 내용 바꾸기 — 두 가지 방법

### 방법 A. 운영자 화면에서 (권장)
1. `admin.html` 열기 → PIN 입력
2. **최종 정답** 탭에서 정답 문장을 바꾸면 글자가 자동으로 GPS 지점에 배정된다
   (단, 지점 수는 `data.js`의 `gpsPoints` 배열을 직접 늘리거나 줄여야 맞춰진다 — 아직 이 화면에서 자동으로 되지 않는다)
3. **퀴즈** 탭에서 문제와 정답을 고친다
4. 다 고쳤으면 **데이터** 탭 → `data.js 내려받기`
5. 받은 파일로 이 폴더의 `data.js`를 덮어쓴다 → 모든 폰에 반영

> 운영자 화면에서 고친 내용은 **그 브라우저에만** 저장된다.
> 4~5번을 해야 다른 기기에도 반영된다.

### 방법 B. `data.js`를 직접 편집
메모장으로 열어서 고쳐도 된다. 구조는 파일 안 주석에 적어뒀다.

## 4. 지금 들어있는 샘플 콘텐츠

- **최종 정답**: `제주에서제일달콤한황금감귤` (13자) — 임시다. 실제 정답으로 바꿀 것
- **퀴즈 40문제 + 최종 문제**: 애니·서브컬처 쉬운 문제. 정답 별칭이 문제당 2~6개 들어있다
- **GPS 지점 13개**: 정답 글자 수와 정확히 같다(고유 글자만, 백업·이벤트 지점은 없앴다)

각 지점의 실제 위경도는 아직 전부 `null`이다. **현장 답사 때 `gps_picker.html`로 직접 찍어서**
`data.js`의 `gpsPoints` 배열에 붙여넣어야 나침반이 작동한다. 도착 인정 반경은
`settings.gpsRadius`(현재 3m)로 전체 조정하거나, 지점별 `radius` 필드로 개별 조정할 수 있다.

> 3m는 상당히 타이트하다. GPS 오차가 보통 5~10m라서, 현장에서 "도착했는데도 안 뜬다"는
> 반응이 나오면 이 값을 5~15m 사이로 올리는 걸 권장한다.

## 5. 미션 QR 인쇄물 만들기

```
python make_qr.py https://실제주소/
```

- `out/미션QR시트_01~02.png` — 스태프 명찰용 미션 완료 QR (A4, 2x3 배치)
- `out/missions/M01.png` — 낱장. 한 장만 다시 뽑을 때

> 보물찾기용 QR은 더 이상 만들지 않는다(전면 GPS 방식으로 교체됨). 이 스크립트는 이제
> 미션 완료 QR(스태프가 들고 있다가 참가자에게 보여주는 것)만 만든다.
> 주소가 바뀌면 미션 QR도 다시 뽑아야 한다. **주소를 먼저 확정하고 인쇄할 것.**

## 6. 아직 안 된 것 (Firebase)

지금은 **폰마다 따로** 저장된다. 그래서:

| 되는 것 | 안 되는 것 |
|---|---|
| 참가자가 혼자 처음부터 끝까지 플레이 | 운영자 화면에서 **다른 폰** 참가자 보기 |
| 오프라인에서도 게임 진행 | 폰을 바꿨을 때 이어하기 |
| 쿠폰 발급·번호 부여 | 여러 스태프가 같은 현황판 보기 |

붙이는 법: `store.js` 맨 위 `var FIREBASE = null;` 에 설정값을 넣고, 그 아래 `flush()` 안에 Firestore 저장 코드를 채우면 된다. **게임 코드(app.js)는 손댈 필요 없다.**

기존 `psbjeju-kuji` 프로젝트를 그대로 써도 되고, 새로 만들어도 된다.

## 7. 행사 당일 순서

1. 개장 전 — 미션 완료 QR(명찰)을 스태프에게 배부, `gps_picker.html`로 찍은 좌표가
   `data.js`에 제대로 반영됐는지 확인
2. 스태프 폰에 `admin.html` 열어두기 (PIN 공유)
3. GPS가 안 잡히거나 오작동한다 → **진행 현황** 탭에서 단서 수동 지급
4. 참가자가 쿠폰 화면을 보여주면 → **지급** 버튼
5. 문제가 생기면 → 우측 상단 **게임 일시중지**
6. 행사 후 — **데이터** 탭에서 참가자 CSV 받고, **전체 참가자 데이터 삭제**

> 6번은 꼭 한다. 이름·전화번호가 저장되어 있고, 등록 화면에서 "7일 내 삭제"를 약속했다.
